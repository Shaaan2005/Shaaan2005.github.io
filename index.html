Featured · Info Origin internship · 2026

AI Resume Screening & RAG Evaluation System

A privacy-first web app that lets a recruiter search a pool of resumes by meaning instead of exact keywords, plus a reproducible benchmark that decides how it ranks candidates.

  • 242sample resumes indexed
  • 48labeled benchmark queries
  • 107automated tests in CI
  • 32 msper search, dense retrieval (one run)

What it does

Matches a recruiter’s query, like “accountant with payroll experience”, to one of 24 job departments, then ranks resumes by their best-matching passage. Text extraction, embeddings and search all run on the host machine, so resumes never go to a cloud API.

My role

I built the first version during my internship at Info Origin, then added the benchmark, the new ranking default and 107 CI tests afterwards. I’m the only contributor.

Read the full case study Pipeline · privacy · limits · full stack

How a search works

  1. 1Extract textPDF & DOCX
  2. 2Chunk200-word pieces
  3. 3Embedall-mpnet-base-v2
  4. 4StoreChromaDB, cosine
  5. 5Detect departmentcross-encoder
  6. 6Rankbest-matching chunk

The problem

Keyword-based screening misses candidates who describe the same skill in different words, and resumes are personal data that shouldn’t go to a cloud API.

Privacy and safety

Everything runs locally; the optional LLM-judged evaluation (RAGAS) can use Llama 3 through Ollama. Uploads are checked by file signature and size, and forms use CSRF tokens.

What these numbers don’t show

  • 48 queries is a small test set.
  • A result counts as relevant if it comes from the query’s job category, so the benchmark can’t judge ordering within a department (say, Python vs. Java engineers).
  • The resumes are a public Kaggle sample (CC0), not a real applicant pool.
  • These are retrieval scores. They don’t measure real-world hiring quality or fairness, and the tool is meant to support a recruiter’s judgment, not replace it.
