Featured · Info Origin internship · 2026

AI Resume Screening & RAG Evaluation System

A privacy-first web app that lets a recruiter search a pool of resumes by meaning instead of exact keywords, plus a reproducible benchmark that decides how it ranks candidates.

The problem

Keyword-based screening misses candidates who describe the same skill in different words. And resumes are personal data, so I didn’t want to send them to a cloud API.

What it does

A Flask app with sign-in, resume upload and semantic search. A query like “accountant with payroll experience” is matched to one of 24 job departments, then resumes in that department are ranked by their best-matching passage. Each result gets a SHORTLIST, CONSIDER or REJECT verdict based on how far its score sits above the rest of the pool.

Privacy-first by design

Text extraction, embeddings and vector search all run on the host machine. The optional LLM-judged evaluation (RAGAS) can use Llama 3 locally through Ollama, so no cloud service is needed. Uploads are checked by file signature and size, and forms are protected with CSRF tokens.

My role

I designed and built the first version during my internship at Info Origin, then kept improving it afterwards: the benchmark, the new ranking default and the test suite came later. I’m the only contributor to the repository, and its 107 tests run on every push through GitHub Actions.

What these numbers don’t show

  • 48 queries is a small test set.
  • A result counts as relevant if it comes from the query’s job category, so the benchmark can’t judge ordering within a department (say, Python vs. Java engineers).
  • The resumes are a public Kaggle sample (CC0), not a real applicant pool.
  • These are retrieval scores. They don’t measure real-world hiring quality or fairness, and the tool is meant to support a recruiter’s judgment, not replace it.

Full-stack · Multi-agent LLM app

DecisionOS: an AI boardroom

A single chatbot tends to agree with whoever is asking. DecisionOS instead runs a structured debate between five advisor agents (CEO, CFO, CTO, risk analyst and mentor), and a chairman agent then writes the verdict, confidence score, key risks and an action plan.

Debates are orchestrated with LangGraph, and past decisions are kept in ChromaDB so later discussions can draw on them. It’s deployed as a web app and installable PWA. I built it on my own.

Backend · Tool-calling agent

Job Tracker Agent

Paste a job posting (text or a URL) and a local Llama 3 agent extracts the company, role, deadline and required skills, compares them with your skills profile and saves the application. You manage everything through a REST API.

I wrote the agent loop by hand instead of using a framework. LLM output is validated with Pydantic, skill matching is plain Python so scores stay deterministic, and every agent step is logged. On 12 hand-labeled synthetic postings, skill extraction scored 0.99 precision and 0.93 recall. That’s a small, synthetic test set.

AI · Retrieval-augmented generation

Multi-Agent Research Assistant

Reading research papers end to end takes a long time, and plain chatbots often misquote them. This Streamlit app splits a paper into page-tagged chunks, and separate agents summarize it, break down its methods, datasets and limitations, and answer questions with page citations.

If the paper doesn’t contain the answer, the app says so instead of guessing. I built it for a midterm project evaluation and wrote an accompanying report in LaTeX. Comparing several papers at once is planned next.

About

I’m an AI engineer finishing a B.Tech in Electronics and Communication Engineering at IIIT Naya Raipur. I work on systems that search, read and reason over text, and I care about measuring whether they help.

I started on the electronics side of my degree, with an Arduino alcohol-detection circuit and a low-power logic library in Cadence Virtuoso. Since then I’ve moved into AI: computer vision during my internship at NTPC, then retrieval and LLM systems at Info Origin.

After the internship I kept working on that system and built a benchmark to test my own design choices. It showed that a re-ranking stage I’d added made results worse, so I removed it from the default. I’ve kept that habit: the job-tracker agent has its own evaluation harness, and the research assistant says so when a paper doesn’t contain the answer instead of guessing.

Right now I’m sharpening my data structures and algorithms, and building more around retrieval, LLM agents and evaluation.
